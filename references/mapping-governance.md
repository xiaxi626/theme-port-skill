# 映射积累治理规则

> 本文件定义 `hexo-port-mappings-*.md` 的置信度、冲突解决和权威优先级。
> 目的：让 `_port` 源主题分析、映射积累、gridea-theme-builder 目标侧参考各归其位，避免模型把“源主题事实”误当成“移植标准答案”。

## 权威层级

1. **gridea-theme-builder 目标侧参考（最高）**
   `template-variables.md`、`theme-architecture.md`、目标引擎 guide、`theme-config-schema.md`。
   任何映射、模板写法、资源路径最终都必须服从这些文件。

2. **映射积累 L1（高置信度先验）**
   经人工确认的跨系统映射，可直接复用，但仍需与目标侧参考交叉验证。

3. **映射积累 L2（自动生成先验）**
   AI 自动推导，仅作参考，不得覆盖 L1。

4. **`_port/` 源主题证据与迁移假设（最低）**
   `01/03/04/05` 只描述“源主题是什么、本次打算怎么迁移”。冲突时修改 `_port/02` 和决策记录，不改目标侧参考，也不因 `_port` 否定已确认映射。

## 来源可信度等级

| 等级 | 来源 | 可信度 | 说明 |
|------|------|--------|------|
| L1（高置信度） | 模式 B（仅积累映射） | ★★★ | 源和目标代码均已人工交叉核对 |
| L2（自动生成） | 模式 A（完整迁移自动写入） | ★★☆ | AI 自动推导，需交叉验证 |

标记格式：

```text
## 来源：{theme-name}（迁移日期：{YYYY-MM-DD}）[L1-高置信度]
## 来源：{theme-name}（迁移日期：{YYYY-MM-DD}）[L2-自动生成]
```

## 冲突解决规则

1. L1 永远覆盖 L2。
2. L1 之间冲突：以最近日期为准，并标注覆盖来源。
3. L2 之间冲突：以最近日期为准，并标注覆盖来源。
4. L2 发现已有 L1 时不覆盖；仅在 L2 备注中标注“与 L1-{主题名} 不一致，保留 L1”。

## 阶段二消费规则

1. 优先采用 L1 映射，并与 `template-variables.md` 交叉验证。
2. L2 映射只作参考，不盲信。
3. 同一变量多个 L1 冲突时，以最新日期的 L1 为准。
4. `_port/01` 只提供源侧证据；最终映射必须落在目标侧能力范围内。

## 阶段七写入规则

- 只有经 `template-variables.md` 或 Gridea 官方行为验证的映射才能标 L1。
- 仅来自某主题专有实现/断言/单一模板名的映射，只能标 L2。
- 每次成功迁移追加来源块，不覆盖已有内容。
- 映射文件仅由阶段七写入；其他阶段不得直接修改映射文件。
