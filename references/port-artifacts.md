# 迁移中间产物规范（_port/）

> 本文档定义 theme-port-skill 逆向分析与复刻审计阶段的中间产物格式。
> 所有产物必须落盘到迁移工作区的 `_port/{THEME_NAME}/` 目录，不得只输出在对话中。
>
> **性质声明：`_port/` 是源主题证据与迁移假设，不是移植标准答案。** 它记录“源主题本来是什么、我们打算怎么处理”；目标侧唯一权威始终是 gridea-theme-builder 的 `template-variables.md`、`theme-architecture.md` 和目标引擎 guide。映射积累文件是经过验证的先验知识。`_port` 与权威知识冲突时，以目标侧权威知识为准，并把差异记录为待确认项。

## 目录规则

1. `_port/` 是迁移执行时**动态创建**的中间产物目录，不是 theme-port-skill 仓库内预置目录。
2. 仓库内不提交 `_port/` 内容；回归测试完成后由用户决定保留或删除。
3. 位置规则：**必须在目标主题的父目录下**创建 `_port/{THEME_NAME}/`。
   - 禁止把 `_port` 创建到与目标主题不同级的目录。
4. 对话中只输出摘要和**需要用户决策**的差异项；完整表格写入对应文件。
5. 阶段五、阶段七必须读取这些文件作为输入，禁止仅依赖对话上下文回忆。

## 产物清单

```text
_port/
└── {THEME_NAME}/
    ├── 01-source-inventory.md      # 阶段一 1.0~1.4：文件清单、依赖图、模板逻辑、设计语言
    ├── 02-variable-map.md          # 阶段二：变量映射表（用户确认版）
    ├── 03-static-map.md            # 阶段一 1.5：静态资源清单与引用闭包
    ├── 04-feature-matrix.md        # 阶段一 1.6：功能清单与迁移决策
    ├── 05-dom-contract.md          # 阶段一 1.7：DOM/类名/状态/样式契约
    ├── static-audit.json           # 阶段五 5.5：audit_static.py 自动生成的审计报告
    └── parity-audit.md             # 阶段五 5.6：原版/迁移版差异审计报告
```

## 写入规则

- 表格中的“证据位置”必须写**文件路径 + 行号或关键片段**，禁止只写“某处”。
- 功能决策为“不可复刻 / 有意裁剪”时，必须明确提示用户确认后才进入阶段三。
- 阶段五 5.6 发现差异后，更新对应产物文件并重新跑相关验证。
